資料快照

每幀一次、由宿主封送處理的唯讀資料。全部存取器都是普通記憶體讀取——零 JNI、零反射、零裝箱。

快照機制

每幀開始時，宿主把該實例的資料一次性封送處理成一塊 POD 快照（定長標頭 + 變長陣列池 + UTF-8 字串池），連同狀態塊指標一起傳給 mtrRender。SDK 的型別化包裝器（mtr::Vehicle、mtr::Pids、mtr::Lift、mtr::EyeCandy）在這塊記憶體上提供與 JS Wrapper 同名的存取器：

  • 字串以 mtr::StrView（data + len）傳回，用 .str() 轉 std::string、.empty() 判斷是否為空；檢視只在本次 render 呼叫內有效。
  • 越界索引擲回 std::out_of_range（與 Java 端 IndexOutOfBounds 語義一致）。
  • 快照指標與包裝器不要跨幀保存。
覆蓋範圍

快照涵蓋高頻讀取的欄位。不在快照裏的資料（網絡、檔案、渲染管理器的深層介面等）經 mtr::Api 存取——那是低頻通道，別在熱路徑用。

Vehicle（車輛）

術語：MTR 3 的 train → MTR 4 的 vehicle

MTR 4 統一以 vehicle 稱呼載具（資源包宣告鍵 vehicleScripts、Java 側 VehicleWrapper），本 SDK 的資料包裝類別因此命名為 mtr::Vehicle。較早版本的 SDK 曾按 MTR 3 慣例命名為 mtr::Train，該名稱現保留為原始碼相容別名——兩種寫法均可編譯，行為完全一致。

注意：mtr::Vehicle 命名已進入倉庫 SDK 原始碼，將隨下一版本的 zip 發佈；若你的專案使用 yanyang.7 及更早的 SDK zip，請以 mtr::Train 引用該類別（新 SDK 中兩種寫法均可編譯）。

交通模式與類型

兩條互補的口徑，與 JS 側 getTransportMode() / getTransportType() 傳回完全相同的值，跨語言腳本可共享佈局邏輯：

  • 模式（mtr::TransportMode 列舉）：UNKNOWN / TRAIN / BOAT / CABLE_CAR / AIRPLANE，涵蓋四種基本載具。
  • 類型（字串 id，mtr::transport_type 常數）：基本模式的小寫名（"train"、"boat"、"cable_car"、"airplane"），加上 MAGIC MTR Addon 的擴展路線類型 train_normal / train_light_rail / train_high_speed / train_metro / train_bus / train_tram / train_sbahn；無法解析時為 "unknown" 或空檢視（舊伺服器資料）。
if (vehicle.getTransportType() == mtr::transport_type::TRAIN_METRO) { /* ... */ }

for (int i = 0; i < stop.interchange_count(); i++) {
    mtr::Stop::Interchange ic = stop.interchange(i);
    if (ic.getTransportType() == mtr::transport_type::TRAIN_HIGH_SPEED) { /* ... */ }
}
資料來源

MAGIC 類型在用戶端裝了該 addon 時從本機設定解析；伺服器裝了而用戶端沒裝時經同步資料集傳送；舊伺服器不下發路線中繼資料時傳回空 / UNKNOWN——裝了本模組的伺服器可提供遠端車站的完整中繼資料。

EyeCandy（裝飾）

mtr::EyeCandy 對應 EyecandyBlockEntityWrapper：

存取器說明
model_id()現時模型 id
translate_x() / _y() / _z() / rotate_x() / _y() / _z()用戶配置的平移 / 旋轉
facing()朝向（MC Direction.ordinal()，0..5）
full_brightness()全亮渲染

is_crosshair_target()是否被準星指向

consume_block_use()消耗一次本幀累積的 onBlockUse 事件（每幀至多一次；同幀多次點擊被合併——與 JS 事件佇列行為一致）
game_time_millis() / in_game_time()時鐘

事件詳情（玩家、手持物品等）經 Api 讀取：

mtr::Api api(ctx.input());
auto event = api.context().call("events").get("onBlockUse");
if (event.call("occurred").as<bool>()) {
    auto detail = event.call("detail");
    auto player = detail.call("player");
    auto item   = detail.call("item");
}

裝飾的繪製上下文 EyeCandyContext 提供 draw_model(model, matrices)、play_sound(sound, volume, pitch)、set_outline_shape(boxes, count)、set_collision_shape(boxes, count)（每箱 6 個 float；碰撞箱沿用 Java 端 1.5 格高度上限，超出由宿主校驗並記日誌）。電梯重用同一上下文類型（LiftContext = EyeCandyContext）。

工具類型

<mtr/util.hpp> 提供熱路徑友好的輪播工具（零配置）：

// "A|B|C" 每 40 tick 輪換一段，檢視切換只做偏移計算
mtr::CycleTracker dest{"KOWLOON|TSUEN WAN"};
StrView current = dest.value(vehicle.in_game_time());
成員說明
CycleTracker(packed, interval_ticks=40)建構輪播（對應 TextUtil.cycleString）
value(game_tick) / value_str(game_tick)現時活躍段（檢視 / 字串）
interval() / part_count()輪換間隔與段數
StrView{data, len} 字串檢視：.str()、.empty()，可 == 比較

繪製與畫布

兩條路線：PIDS 螢幕用 Text / Texture 串流 API 直出；像素級內容（LCD、點陣螢幕）用 GraphicsTexture + Gfx2D 原生光柵。

本頁內容
  1. Text 與 Texture（PIDS）
  2. Matrices 與模型繪製
  3. GraphicsTexture（像素畫布）
  4. Gfx2D 軟件光柵器
  5. 字型體系
兩條路線怎樣選

螢幕座標系內容（PIDS 文字行、貼圖塊）→ Text/Texture：一條繪製記錄，宿主用與 JS 完全相同的程式碼路徑回放。像素級內容（車輛 LCD、動態點陣螢幕、圖表）→ GraphicsTexture 自繪像素，經 Gfx2D 光柵化基元，只把髒矩形上載 GPU。

Text 與 Texture（PIDS）

<mtr/text.hpp> 是 JS TextWrapper / TextureWrapper 串流 API 的 1:1 移植——方法名按 C++ 慣例 snake_case，鏈式呼叫：

mtr::Text::create()
    .text("Tsim Sha Tsui")
    .scale(1.725)
    .size(100, 9)
    .stretch_xy()
    .font_mc()
    .color(0xFC9700)
    .pos(3, rowY)
    .draw(ctx);
Text 方法對應 JS說明
.text(str[, len]).text()UTF-8 文字
.scale(s).scale()整體縮放
.left_align() / .center_align() / .right_align()同名對齊（預設置中）
.shadowed() / .bold() / .italic()同名字飾
.stretch_xy() / .scale_xy() / .wrap_text() / .marquee(duration)同名溢出模式（跑馬燈可用 .with_marquee_progress(p) 固定進度）
.font(id) / .font_mc()同名資源字型（如 .font("jsblock:shanghai")）/ MC 內置字型
.color(argb)同名顏色（ARGB）
.pos(x, y) / .size(w, h)同名螢幕座標與包圍盒
.z_order(z) / .layer(l)同名層級；z=-1 時由上下文自動指派
Texture 方法說明
.texture(id)貼圖資源 id（如 "mtr:textures/block/pids.png"）
.uv(u1, v1, u2, v2)UV 子矩形
.color(argb)染色
.pos(x, y) / .size(w, h)位置與尺寸
.z_order(z) / .layer(l)層級

配套上下文方法（PidsContext）：

  • ctx.set_auto_z_ordering(bool) —— 自動 z 序（預設開啟）
  • ctx.set_z_order_step(step) —— 自動 z 序步長（預設 0.0002）

渲染層（mtr::Matrices 無關的 2D 層列舉 MtrRenderLayer）：MTR_LAYER_TEXT（文字）、MTR_LAYER_LIGHT（發光體）、MTR_LAYER_EXTERIOR / MTR_LAYER_INTERIOR（外觀 / 內飾），與 MTR 的 QueuedRenderLayer 一致。

Matrices 與模型繪製

<mtr/matrices.hpp> 對應 JS 的全域 Matrices：變換推入堆疊、compile() 把現時堆疊編譯為一組矩陣寫進幀矩陣競技場：

mtr::Matrices m;
m.translate(0.5f, 1.0f, 0.0f);
m.rotate_y_degrees(90.0f);
m.scale(1.0f, 1.0f, 1.0f);
ctx.draw_car_model(model_handle, car_index, &m);   // 車輛
ctx.draw_model(model_handle, &m);                   // 裝飾 / 電梯
成員說明
translate(x, y, z) / scale(x, y, z)平移 / 縮放
rotate_x / rotate_y / rotate_z(radians)旋轉（弧度）
rotate_x_degrees / …_y… / …_z…(deg)旋轉（角度）
compile()把現時姿態編譯進幀（傳回矩陣組索引；傳給 draw 呼叫）

車輛上下文另有 draw_bogie_model(model, car, bogie, matrices)（轉向架）、play_car_sound(sound, car, x, y, z, volume, pitch) 與 play_ann_sound(sound, volume, pitch)（僅乘坐玩家可聽到的報站廣播）。

模型控制代碼來自宿主服務：ctx.host()->acquire_model(user, "namespace:path/model.json") 取得、release_model(user, handle) 釋放；acquire_quad_model(...) 可用 4 個模型空間頂點 + UV 建構宿主持有的貼圖面片（把 GraphicsTexture 變成可貼到車廂上的螢幕）。細節見 C ABI 與宿主服務。

GraphicsTexture（像素畫布）

<mtr/gfx.hpp> 的 GraphicsTexture 把像素緩衝區留在你的模組裏，遊戲側只收髒矩形上載——像素資料不逐幀跨邊界搬運：

struct LcdState {
    mtr::GraphicsTexture tex;      // 建議放 State：與實例同生命週期
};

void create(mtr::VehicleContext& ctx, LcdState& s, const mtr::Vehicle&) {
    s.tex.create(ctx.input(), 512, 128);   // 同時向宿主註冊 GPU 紋理
    // 把紋理貼到車廂：host->acquire_quad_model(...) → draw_car_model(...)
}

void render(mtr::VehicleContext& ctx, LcdState& s, const mtr::Vehicle& vehicle) {
    // 1. 畫像素（Gfx2D 或直接 set_pixel）
    // 2. 只上載變化區域：
    s.tex.upload(ctx.frame());
}
成員說明
create(input, w, h)配置像素緩衝區（BGRA8 行主序）並在宿主側建立 GPU 紋理，傳回後整體視為髒
pixels() / pixels32()直接像素指標（uint8_t* / uint32_t*）
set_pixel(x, y, argb)寫單一像素並自動累計髒區
upload(frame)把現時髒矩形寫入幀像素競技場（一條 JCM_DRAW_TEXTURE_UPLOAD 記錄），隨後髒區復位
last_upload_bytes()上次上載的位元組數——效能觀測利器
close(input) / 解構釋放宿主 GPU 紋理
handle() / width() / height() / texture_bytes()宿主紋理控制代碼與尺寸資訊
效能要點

upload() 只搬運自上次上載以來變化過的包圍盒。靜態背景畫一次即可；每幀只動需要動的條帶（跑馬燈、閃爍段、進度條）。車輛 LCD 閃爍／輪播如果只改一小條，上載量就只有那一小條。

同一標頭檔還提供 LcdCanvas——基於內置 5×7 點陣字型的 LCD 畫筆（可配置亮／熄顏色），適合經典點陣螢幕。

Gfx2D 軟件光柵器

<mtr/gfx2d.hpp> 把 java.awt.Graphics2D 的常用子集實作為確定性軟件光柵器，直接畫在 GraphicsTexture 上。JS 資源包裏的 fillRect / fillOval / drawLine / GeneralPath / clip / drawString 邏輯可以機械地移植過來：

mtr::Gfx2D g(s.tex, ctx.host(), "jsblock:shanghai");  // 畫布 + 宿主字型

g.set_color(mtr::clr(12, 28, 44));                    // 深色底
g.fill_rect(0, 0, W, H);

g.push_clip(8, 8, W - 16, 40);                       // 裁剪堆疊
g.set_color(mtr::clra(255, 205, 66, 255));
g.draw_text_centered(W / 2, 30, 18.0, "下一站 Next");
g.pop_clip();
基元說明
fill_rect / fill_round_rect / draw_round_rect矩形（圓角弧半徑參數）
fill_oval / draw_oval橢圓填充 / 描邊（線寬）
draw_line(x1, y1, x2, y2, lw)線段
fill_polygon(xs, ys, n)多邊形填充（GeneralPath 等價）
push_clip / pop_clip裁剪框堆疊；所有基元先裁剪再光柵，髒區同樣被裁剪約束
draw_text / draw_text_centered / draw_text_compressed / draw_mixed_text文字（見下節字型）
draw_logo_badge(x, y, w, h, bg, fg)圓角徽章底色

顏色助手：mtr::clr(r, g, b) / mtr::clra(r, g, b, a)（不透明 / 帶 alpha），對應 JS config.js 裏的同名函式。半透明顏色走 src-over 合成；不透明顏色有快速路徑。

字型體系

三層字型，按可用性自動降級：

層級覆蓋說明
資源字型（首選）全 UTF-8給 Text::font("jsblock:shanghai")、Gfx2D 建構第三參傳字型資源 id：用宿主的真實 FontMetrics 與 drawString，保留字距、基線、壓縮、alpha 與裝置裁剪——和 JS 端同一字型管線
宿主 TTF 回呼CJK 等無資源字型時，CJK 字形經宿主服務 rasterize_text 光柵化（對應 JCM FontManager 的 TTF 集）
內置 5×7 點陣字型ASCII / 拉丁按請求尺寸縮放、按字形寬窄給比例步進（窄的 i、l、.、,；寬的 m、W）——text_width() 與實際繪製用同一組數字，JS 的自適應字號 / 5% 壓縮排版演算法可原樣移植；CJK 無宿主時退化為佔位框

內置字型的度量約定：ascent = 0.78 em、descent = 0.22 em（≈ Arial / HanSans）；CJK 全形 1.0 em 步進。資源字型的度量（measure_font_text 宿主服務）按真實字型計算。

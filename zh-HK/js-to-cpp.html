JS → C++ 遷移

把既有 JS 腳本移植成 C++ 原生腳本。兩條管線共享幾乎一一對應的包裝器語意——移植主體是改名與重塑，不是重寫。

為何遷移

先讀兩頁

遷移前先看腳本模型與生命週期（create / render / dispose + 逐實例 State 在兩側完全同構）與JS 腳本入門——本頁只講兩側差異。

  • 一次封送代替數百次反射：JS 側每讀一個欄位都是一次跨語言呼叫；C++ 側整塊快照是平鋪 POD，腳本按普通記憶體讀取。
  • 零 GC 壓力：沒有包裝器物件與裝箱字串；繪製記錄在記憶體區內 bump 配置。
  • 崩潰防護：出錯的模組自動停用（native script faulted: module disabled），絕不弄崩遊戲。
  • 新能力原生優先：模型著色 / 發光 / 半透明、訊號擴充點、道口 / 售檢票機 / 廣播三類方塊腳本（ABI 16）。
  • 何時留在 JS：一次性小腳本、沒有編譯工具鏈、需要飛快迭代——選型對照見概覽。

生命週期與註冊

三個生命週期函式換成虛函式 override；跨幀狀態從閉包變數搬進 State 結構。註冊巨集隨腳本類型選擇，資源包宣告與 JS 條目同一管線。

JavaScriptC++說明
function create(ctx, state, pids)void create(PidsContext& ctx, State& state, const Pids& pids) override首次渲染前執行一次
function render(ctx, state, pids)void render(...) override每幀執行（盡力而為節律與 JS 相同）
function dispose(ctx, state, pids)void dispose(...) override實例退場清理
跨幀存活的閉包變數State 結構成員宿主配置、placement-new；基類模板參數換成你的 State 類型
SCRIPT_INPUT JSONapi.input()mtr::Api（ABI 8+），同一份資源包宣告輸入

註冊：MTR_REGISTER_PIDS_SCRIPT(MyScript)——車輛 / 電梯 / 裝飾 / 屏蔽門 / 道口 / 售檢票機 / 廣播分別用 MTR_REGISTER_VEHICLE_SCRIPT / _LIFT_ / _EYECANDY_ / _PSD_ / _LEVEL_CROSSING_ / _FARE_MACHINE_ / _ANNOUNCEMENT_。每個模組一個腳本 id，照舊在 mtr_custom_resources.json 裏宣告（scriptLocations 分類規則不變）。

無對應物（手工移植）

沒有攣生兄弟

下面這些 JS 設施在原生側沒有一一對應物，需按右欄改寫——轉換器也會在這些位置留 TODO。

JS 設施手工移植做法

半自動轉換器

SDK 自帶 tools/js2cpp.py（純標準庫、零依賴），把上表的機械部分自動化：

python3 native/tools/js2cpp.py input.js -o output.cpp --id mypack:pids --kind pids

它執行本頁全部改名規則、forEach → 索引迴圈、TextWrapper 鏈 → mtr::Text 鏈、屬性存取 → getter、模組級變數搬進 State 欄位（型別推斷 + state. 前綴改寫）、Math / console 基礎改寫；不確定處絕不靜默改寫，全部留 TODO 標記。

產出預期：一份直接可編譯的骨架 + 少量 TODO。隨後照編譯一節建構，用熱重載在遊戲裏迭代。

端對端示例

同一個「首行到站」PIDS 腳本的兩種寫法：

let PREFIX = "";                 // 模組級常數

function create(ctx, state, pids) {
    state.ticks = 0;             // 逐實例狀態
}

function render(ctx, state, pids) {
    state.ticks++;
    const next = pids.arrivals().get(0);
    const dest = next ? next.destination : "無列車";

    new Text(PREFIX + dest)
        .pos(0, 0).size(pids.width, 14)
        .centerAlign().draw(ctx);
}
#include <mtr/script.hpp>

struct FirstArrivalState { int ticks = 0; };   // 逐實例狀態

struct FirstArrival : mtr::PidsScript<FirstArrivalState> {
    static constexpr auto ID = "example:first-arrival";

    void render(mtr::PidsContext& ctx, FirstArrivalState& state,
                const mtr::Pids& pids) override {
        state.ticks++;

        const auto arrivals = pids.arrivals();
        mtr::StrView dest = arrivals.size() > 0
            ? arrivals.at(0).destination() : mtr::StrView{"無列車"};

        mtr::Text::create()
            .text(dest.str().c_str())
            .pos(0, 0).size(pids.width(), 14)
            .center_align().draw(ctx);
    }
};

MTR_REGISTER_PIDS_SCRIPT(FirstArrival)
  • 邏輯逐行對得上：get(0) 的空值檢查換成 size() > 0 判空（JS 的 get 越界回傳 null，C++ 的 at 越界拋例外——語意差異見資料快照）。
  • Timing.now() 類時鐘全部換成快照存取器；閉包變數 state.ticks 原樣保留在 State 裏。
  • 資源包宣告側：遷移期可讓 JS 版與 C++ 版以各自獨立的 id 並存於同一資源包（scriptLocations 支援混合宣告），逐屏核對輸出一致後，再把條目切到 C++ 一側——宣告格式見打包。

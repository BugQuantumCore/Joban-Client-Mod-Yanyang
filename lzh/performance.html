性能與除錯

使腳本行且疾且穩：熱路徑之守則、記憶體之衛生，暨事出之時所當觀者。

性能之模型

每幀每實例之費，其構如次：

環節所費
快照封送（宿主 → 模塊）唯一所迫之 Java 穿越：宿主以復用建構器書 POD 快照於共享頁 / 直接緩衝
數據之讀（Vehicle / Pids / …）尋常記憶體之讀，零費
繪製記錄之書競技場內 bump 分配，零分配零裝箱
像素光柵（Gfx2D）純 C++ 之環；src-over 不透明有快捷之途
宿主回放與 JS 同一渲染之途；紋理上傳惟搬髒矩形
Api 之呼JSON 編碼＋反射＋JSON 解碼之往返——費巨 惟作低頻之通道

熱路徑守則

  1. render 之內勿近 Api。高頻數據盡在快照；高頻繪製盡行記錄之流。JS 之世週期性 GC 之頓挫，正「每幀每車一反射之呼」所致也。
  2. 資源惟建於 create：模型、紋理、Java 物件之柄、回呼——既建則存 State，render 惟用之。
  3. 勿逐幀讀資源 / 行 HTTP：網路入 BackgroundWorker，所得入君自家同步之緩存，render 讀緩存。
  4. 紋理惟內容既變乃上傳：靜態之景繪一次；動態之內容以 push_clip 限重繪之域，使髒矩形惟覆真變之條。
  5. 逐物件錯其相：多實例輪播 / 閃爍勿同幀齊動——以相錯之調度散髒區於諸幀（以 in_game_time() 或 game_time_millis() 為鐘）。
  6. 字串暫物宜節：StrView 相較免抄；確須拼接，則慎 std::string 之分配（短串 SSO 免分配）。

記憶體與延遲回收

宿主側記憶體之紀（腳本作者知之可也，SDK 自蒙其利）：

  • 五輸出競技場每模塊一份、幀間復用；像素競技場初 1 MB、按需而增（上限 16 MB）、尖峰既過則確定收縮復歸下限——不復有每模塊 16 MB 之固定駐留。
  • 實例去視錐而不毀（保其熱態、重入於鏡則零重建）；誠去客戶端車輛之列，約五秒乃退休。
  • 大塊之釋行 defer_free（ABI 10）：render / dispose 之內既死之兆級緩衝，付宿主後臺回收之線程，免記 free 全費於當前之幀、且免大 GC 安全點之待。其約曰：塊必既死、無析構、此後無線程（含宿主回放）復觸之。SDK 像素競技場之收縮已自遵之；君自有之大緩衝循同規而呼 host->defer_free，宿主過舊（槽為 null）時同步 free 可也。

觀測與日誌

所觀所在內容
模塊 censuslogs/latest.log 啟動之段已載模塊之數與類；傳輸通道摘要之行（含 transport: 之樣：shared-memory / panama-ffm 等）——以證 shm / FFM 誠已生效、有無靜默降級
載失之由census 行＋除錯之模一側（JS 或 C++）缺 / 載敗，惟略彼側而留其示，餘側行如常
崩潰圍欄latest.lognative script faulted: code=… module disabled——模塊見禁之確由
清掃之流latest.log（每分鐘一行）實例銷毀節奏之彙錄，得徑觀實例壽命之行
上傳位元組之數GraphicsTexture::last_upload_bytes()於君之碼中誌之：髒矩形之策效否，一覽而知

既改庫，按 F3+T（或模組「重載全部 MTR 腳本」之快捷鍵）即可重載 C++ 腳本——卸載與復尋皆行全程，無須重啟遊戲。

JVM 參數

參數預設所司
-Djcm.nativeIdleMillis90000實例猶存而久未渲染，逾此毫秒之數乃釋；0 = 不依時限而釋
-Djcm.nativeIdleMax32熱實例之上限，踰者以最久未渲染者先釋；0 = 不設上限
-Djcm.ffm.disable關除錯之關：禁 Panama FFM 載入之途

實例退休與銷毀，別有每 tick 之預算（預設 2 個、舊者先出），暨世界卸載 / 切換維度 / 斷線之時一次性沖刷。

常見之問

模塊全然不載，何也？

  1. 先察所用為 Release 或 Complete Build jar——速成 CI 之產物不含原生橋，日誌必書 native bridge unavailable（此非君模塊之過）。
  2. 次察平臺之目：當前系統惟載所應平臺之庫；無副檔名之 stem 宣告自展為諸平臺之路（見打包）。
  3. 復察 ID 與宣告條目之 id 是否逐字相合。
  4. 終察 ABI：宿主受 6–10；ABI 8+ 之庫須 Yanyang.7 及以上之宿主。

屏現占位之框（tofu），何也？

CJK 字形，宿主字體不覆該碼位則退——以資源字體 id 傳於 Text::font() / Gfx2D 之構造（如 jsblock:shanghai），或察所用字體之集果含此諸字否。

間或失幀，何也？

  • 先觀是否「每幀重繪全屏」：靜態之內容繪一次，動態之內容 clip 條帶而重繪，以 last_upload_bytes() 驗之。
  • 次觀是否多實例同幀齊動：輪播 / 閃爍 / 開門之動，逐物件錯其相。
  • 終察 render 之內有無 Api 之呼（兼間接者：ctx.set_auto_z_ordering 等一二上下文之法，於 ABI 8+ 將轉發一遭）。

Windows 上所行與他處異，何也？

ABI 6 之前之古版，嘗恃「零填充之記憶體可徑作物件用」——此恰惟於 MSVC 布局之下倖存。今 SDK mtrInit() 之約已根治之；君若撰自定義宿主，務於配狀態塊之後呼 mtrInit()。

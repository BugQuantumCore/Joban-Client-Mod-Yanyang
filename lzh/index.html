C++ 原生腳本

為 Minecraft Transit Railway 4 資源包之作者而設：以 C++ 撰車輛、PIDS、電梯、裝飾四類腳本——與 JavaScript 腳本同生命週期、同 API 面，熱路徑零 JVM 穿越。

此為何物

Joban Client Mod（JCM）原版許資源包以 JavaScript 撰動態顯示之腳本。Yanyang 分支於斯增益 C++ 原生腳本：編腳本為本機共享庫（.dll / .so / .dylib），由模組載之於遊戲之內，逐幀驅之。

C++ 腳本與 JS 腳本得混用於同一宣告條目、並時渲染。模組按文件之特徵自判其語——.js 者 JavaScript 也，餘皆按 C++ 模塊解之。兩側各捕繪製之令、各自回放，兩不相擾。

🧩

同式腳本模型

create / render / dispose 生命週期與逐實例恆存之狀態，與 JS 全同；快照包裝器逐欄位對齊 JS Wrapper。

⚡

零 JNI 傳輸

Java ↔ C++ 之通，或經共享記憶體輪詢平面（任意 JDK ≥ 16），或經 Panama FFM（JDK 22+），全程不涉 JNI；每幀每實例惟一遭宿主穿越而已。

🖥️

七平臺原生橋

windows-x64 / linux-x64 / linux-arm64 / android-arm64 / macos-x64 / macos-arm64 / ios-arm64 諸橋悉內置於 jar，按系統架構自動匹配。

🛡️

崩潰隔離

腳本崩潰，惟禁出事之模塊本身，留日誌一行，遊戲行程不為所擾；模塊內之 C++ 異常亦為圍欄所截。

十五行 PIDS 腳本

examples/pids_arrivals.cpp — 到站顯示
#include <mtr/script.hpp>

struct ArrivalState {};

struct ArrivalDisplay : mtr::PidsScript<ArrivalState> {
    static constexpr auto ID = "example:arrivals";

    void render(mtr::PidsContext& ctx, ArrivalState&, const mtr::Pids& pids) override {
        for (int row = 0; row < pids.rows(); row++) {
            if (pids.is_row_hidden(row)) continue;
            std::string text = pids.get_custom_message(row).str();
            if (text.empty() && row < pids.arrivals().size())
                text = pids.arrivals().at(row).destination().str();
            if (!text.empty())
                mtr::Text::create().text(text.c_str())
                    .pos(2, row * 10.0 + 2).size(pids.width() - 4, 9).draw(ctx);
        }
    }
};

MTR_REGISTER_PIDS_SCRIPT(ArrivalDisplay)

無 JNI、無反射、無逐呼叫之裝箱——pids.rows()、arrivals().at(i).destination() 皆緊湊快照上尋常記憶體之讀耳。

何時宜用 C++

場景所宜
高解析度 LCD / 點陣屏，每幀重繪巨量像素C++ Gfx2D 軟體光柵＋髒矩形（dirty rectangle）上傳，像素不越 JVM
繁難字串之處理 / 逐幀排序 / 算學之運算C++ 原生計算，分配全無
須頻喚 Java API（網路、檔案、聲音管理器）皆可 兩側皆得經 Api 訪同一批公開物件
簡單一次性顯示之邏輯JS 無須編譯工具鏈，更迭其疾

相容性

項目所需
Minecraft1.17.1 – 1.20.4（Fabric / Forge）
前置Minecraft Transit Railway 4.0.5+（必需）；Fabric 版另需 Fabric API
Java16 及以上；22+ 自動啟用全程零 JNI 之 FFM 平面
ABI宿主受 ABI 6–10 之模塊；今之 SDK 編譯所出為 ABI 10
工具鏈C++17；MSVC / GCC / Clang；CMake ≥ 3.16（薦）

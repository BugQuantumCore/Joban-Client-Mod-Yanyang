數據快照

每幀一遭，宿主封送之唯讀數據也。諸訪問器所為，皆尋常記憶體之讀——零 JNI，零反射，零裝箱。

本頁之目
  1. 快照之機
  2. Vehicle（車輛）

快照之機

每幀方始，宿主以此實例之數據一舉封送，為一 POD 快照：定長之首，變長之陣列池，UTF-8 字串之池，三者具焉；連狀態塊之指針，併傳於 mtrRender。SDK 之具型包裝器（mtr::Vehicle、mtr::Pids、mtr::Lift、mtr::EyeCandy）居此記憶體之上，供與 JS Wrapper 同名之訪問器：

  • 字串以 mtr::StrView（data＋len）而返；.str() 則轉為 std::string，.empty() 則判其虛實。視圖惟本次 render 一呼之內為效。
  • 索引越界，則擲 std::out_of_range（與 Java 端 IndexOutOfBounds 同其義也）。
  • 快照之指針與包裝器，慎勿跨幀而存之。
所覆之範

快照所覆者，高頻讀取之欄而已。數據之不在快照者（網路也，檔案也，渲染管理器之深介面也），則經 mtr::Api 而訪之——彼固低頻之通道，勿用於熱路徑也。

Vehicle（車輛）

術語：MTR 三代之 train → MTR 四代之 vehicle

MTR 四代之制，載具統名曰 vehicle（資源包宣告之鍵 vehicleScripts，Java 側則 VehicleWrapper 是也），故本 SDK 數據包裝之類，名之曰 mtr::Vehicle。前代 SDK 嘗循 MTR 三代之舊，名之曰 mtr::Train；今舊名猶存，為源碼相容之別名——二名並可編譯，所行全同。

按：mtr::Vehicle 之名已入倉庫 SDK 之原碼，將隨次版之 zip 而布；君所用若 yanyang.7 或更早之 SDK zip，則請以 mtr::Train 名之（新 SDK 之中，二名並可編譯）。

mtr::Vehicle 所供者，映 JS 之 VehicleWrapper 加 NTETrainWrapper：

Stop / 轉乘 / 出口

mtr::Stop 映 JS 之 VehicleWrapper.Stop：

訪問器釋義
name()站名
destination_name()該站台終點站顯示之名
has_custom_destination() / custom_destination()自定之終點站（未設者，JS 返 null；C++ 則以 has_custom_destination() 判之）
distance()軌道之進（不可用時為 -1）
dwell_time_millis()該站停站之時
route_id() / station_id() / platform_id()線路 / 車站 / 站台之 id（64 位）
is_route_switchover()線路切換之站否
route_circular_state()該站所屬線路之環線狀（所以辨跨線後方向之變也）
interchange_count() / interchange(i)轉乘之訊：每條含 color（ARGB）、name（線路名）、getTransportMode()、getTransportType()
exit_count() / exit(i)車站之出口：每個含 name（出口之字母，如 "A"）與 destination(j)（地標字串之列）

交通之模式與類型

二者相補之口徑也；與 JS 側 getTransportMode() / getTransportType() 所返之值全同，故跨語言之腳本，得共享布局之邏輯：

  • 模式（mtr::TransportMode 枚舉）：UNKNOWN / TRAIN / BOAT / CABLE_CAR / AIRPLANE，覆基礎載具凡四。
  • 類型（字串 id，mtr::transport_type 常數）：基礎模式小寫之名（"train"、"boat"、"cable_car"、"airplane"），益以 MAGIC MTR Addon 所擴線路之類 train_normal / train_light_rail / train_high_speed / train_metro / train_bus / train_tram / train_sbahn；其不可解者，則為 "unknown"，或空視圖（舊伺服器之數據也）。
if (vehicle.getTransportType() == mtr::transport_type::TRAIN_METRO) { /* ... */ }

for (int i = 0; i < stop.interchange_count(); i++) {
    mtr::Stop::Interchange ic = stop.interchange(i);
    if (ic.getTransportType() == mtr::transport_type::TRAIN_HIGH_SPEED) { /* ... */ }
}
數據所自

MAGIC 諸類之所自：客戶端裝其 addon 者，自本地之配置而解；伺服器裝而客戶端未裝者，經同步數據集而下；舊伺服器不下線路元數據者，返空 / UNKNOWN——裝本模組之伺服器，則供遠端車站以完備之元數據。

Pids（到站之屏）

mtr::Pids 映 JS 之 PIDSWrapper：

訪問器釋義
width() / height()顯示屏之寬高（1.0 單位 = 16 px，螢幕坐標系）
rows() / is_row_hidden(i)文字之行數 / 第 i 行隱否（至多 32 行）
station_id()所在車站之 id
is_key_block() / is_platform_number_hidden()按鍵方塊否（司隱他屏）/ 隱站台之號否
get_custom_message(i)第 i 行自定之訊；未設則返空（JS 則返 null）
arrivals()Arrivals：到站之列（見下）
game_time_millis() / in_game_time()時鐘（已正伺服器之偏）

Arrivals / Arrival

訪問器釋義
arrivals().size() / .at(i)到站條目之數，與逐條之訪
arrivals().next_for_platform(platform_id, out, cursor)按站台之序而歷（映 JS 之 forEach(platformId, cb)）；游標復用，分配則無
arrivals().mixed_car_length()各條目車廂之數一否（映 mixedCarLength()）
destination() / route_name() / route_number() / platform_name()終點站 / 線路名 / 線路號 / 站台名
arrival_time() / departure_time() / deviation()到站 / 離站之刻與其偏（epoch 毫秒，已正）
arrived() / departed()已到站 / 已離站否（按當前之刻而較）
realtime() / terminating() / circular_state()即時之據 / 本班之終 / 環線之狀
route_id() / platform_id() / route_color() / car_count() / departure_index()線路 / 站台之 id、線路之色 ARGB、車廂之數、發車之序

Lift（電梯）

mtr::Lift 者，快照與 Java 包裝器相合之制；此其快照之部也：

訪問器釋義
id()電梯實例之 id
should_render() / is_double_sided() / is_client_player_riding()渲染 / 雙面 / 玩家乘焉
width() / height() / depth()尺寸
door_value()門之開度 0..1
angle_degrees() / angle_radians()朝向之角
direction()行進之向
floor_count() / floor(i)樓層之表：每層含 index，current_floor / target_floor 之標，position[3]，暨樓層之號與描述之字串（經 string(offset,len) 而取）
game_time_millis() / in_game_time()時鐘

渲染管理器、聲音管理器、可見性諸深介面，經 Api 之 wrapper() 而訪之（電梯無獨立之 JS 文檔頁，故以 Java 包裝器為準）。

EyeCandy（裝飾）

mtr::EyeCandy 映 EyecandyBlockEntityWrapper：

訪問器釋義
model_id()當前模型之 id
translate_x() / _y() / _z() / rotate_x() / _y() / _z()用戶所配之平移 / 旋轉
facing()朝向（MC Direction.ordinal()，0..5）
full_brightness()全亮渲染
redstone_level()紅石之訊 0..15
is_crosshair_target()準星所指否
block_pos(i)方塊坐標之分量（i = 0..2）
consume_block_use()銷本幀所積 onBlockUse 事件之一（每幀至多一遭；同幀連擊，則併而為一——與 JS 事件佇列之行同也）
game_time_millis() / in_game_time()時鐘

事件之詳（玩家、手持之物等），經 Api 而讀之：

mtr::Api api(ctx.input());
auto event = api.context().call("events").get("onBlockUse");
if (event.call("occurred").as<bool>()) {
    auto detail = event.call("detail");
    auto player = detail.call("player");
    auto item   = detail.call("item");
}

裝飾繪製之上下文 EyeCandyContext，所供者四：draw_model(model, matrices)、play_sound(sound, volume, pitch)、set_outline_shape(boxes, count)、set_collision_shape(boxes, count) 是也（每匣 6 float；碰撞匣之高，沿 Java 端 1.5 格之限，踰之者宿主校而誌於日誌）。電梯復用同一上下文之型（LiftContext = EyeCandyContext）。

器用之型

<mtr/util.hpp> 供輪播之器具，於熱路徑甚友善（零分配）：

// "A|B|C" 每 40 tick 更迭一段，切視圖惟算偏移
mtr::CycleTracker dest{"KOWLOON|TSUEN WAN"};
StrView current = dest.value(vehicle.in_game_time());
成員釋義
CycleTracker(packed, interval_ticks=40)構輪播（映 TextUtil.cycleString）
value(game_tick) / value_str(game_tick)當前活躍之段（視圖 / 字串）
interval() / part_count()更迭之隔與段數
StrView{data, len} 字串之視圖：.str()、.empty()，可比之以 ==

繼之：繪事與畫布 —— 取此數據而繪之。
